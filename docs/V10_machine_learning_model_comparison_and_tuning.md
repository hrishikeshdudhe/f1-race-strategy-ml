# V10 — Machine Learning Model Comparison and Tuning

## Overview

V10 extends the F1 race strategy simulation project with a machine learning evaluation framework.

The objective is to predict the simulated total race time of a strategy from its strategy characteristics.

The V10 workflow evaluates multiple regression approaches, validates their performance using k-fold cross-validation, analyzes feature importance, and performs a controlled hyperparameter comparison for Gradient Boosting.

The dataset used in this project is generated by the project's own race strategy simulator and is therefore synthetic rather than historical Formula 1 race data.

---

## Machine Learning Workflow

The V10 workflow consists of the following stages:

1. Generate race strategies using the simulation framework.
2. Extract numerical features from each strategy.
3. Split the dataset into training and test sets.
4. Establish a mean-value baseline.
5. Train and evaluate multiple regression models.
6. Analyze prediction errors and model features.
7. Perform 5-fold cross-validation.
8. Compare Gradient Boosting hyperparameter configurations.
9. Select the strongest configuration among the tested configurations.
10. Perform the final cross-validation evaluation.

The overall architecture is:

```text
Race Strategy Simulator
          |
          v
   Strategy Dataset
          |
          v
   Feature Extraction
          |
          v
   +----------------+
   | Training/Test  |
   | Split          |
   +----------------+
          |
          +------------------+
          |                  |
          v                  v
    Model Comparison    Cross Validation
          |                  |
          +--------+---------+
                   |
                   v
          Hyperparameter Tuning
                   |
                   v
          Final Model Evaluation
```

## Dataset

The experiment generates:

- 50-lap races
- 441 evaluated strategies
- 352 training samples
- 89 test samples

The target variable is the simulated total race time in seconds.

The dataset is deterministic for the experiment configuration, allowing reproducible model comparisons.

---

## Features

The strategy feature extractor produces features describing the structure of each strategy.

### Strategy-level features

- `number_of_stints`
- `number_of_pit_stops`
- `total_laps`
- `pit_stop_time_seconds`

### Tire compound features

- `soft_stints`
- `medium_stints`
- `hard_stints`

### Stint distribution features

- `average_stint_laps`
- `shortest_stint_laps`
- `longest_stint_laps`
- `stint_lap_range`

### Individual stint features

Dynamic features are also generated for individual stints, such as:

- `stint_1_laps`
- `stint_2_laps`

and additional stint features when applicable.

## Models

V10 evaluates three regression approaches.

### Linear Regression

Linear Regression provides a simple interpretable baseline for understanding relationships between strategy features and predicted race time.

Its coefficients can be inspected to understand the direction and magnitude of the learned relationships.

### Random Forest

Random Forest is an ensemble of decision trees.

It can represent nonlinear relationships between strategy characteristics and race time and provides feature importance measurements.

### Gradient Boosting

Gradient Boosting builds an ensemble of decision trees sequentially, with later trees improving errors made by earlier trees.

The model also provides feature importance measurements.

---

## Baseline

A mean-value baseline is included to establish a simple reference point.

For the evaluated dataset:

```text
MAE:  10.107 s
RMSE: 11.857 s
R²:   -0.0045
```

The negative R² indicates that predicting the mean race time provides little explanatory value for the variation in the generated strategy results.

---

## Initial Model Comparison

The initial 80/20 train-test evaluation produced:

| Model | MAE | RMSE | R² |
|---|---:|---:|---:|
| Mean baseline | 10.107 s | 11.857 s | -0.0045 |
| Linear Regression | 3.215 s | 4.508 s | 0.8548 |
| Random Forest | 2.054 s | 3.297 s | 0.9223 |
| Gradient Boosting | 1.571 s | 2.617 s | 0.9511 |

These results show that the tree-based models captured nonlinear relationships in the generated strategy data more effectively than the linear model.

The evaluation is specific to this synthetic dataset and should not be interpreted as evidence of performance on real Formula 1 data.

---

## Cross-Validation

To reduce dependence on a single train-test split, V10 uses 5-fold cross-validation.

Each model is trained and evaluated five times using different training and validation partitions.

The results are summarized using:

- mean MAE
- standard deviation of MAE
- mean RMSE
- standard deviation of RMSE
- mean R²
- standard deviation of R²

The initial Gradient Boosting configuration used:

```text
n_estimators = 100
learning_rate = 0.10
max_depth = 3
```

Its 5-fold result was:

```text
Mean MAE:  1.813 s
Std MAE:   0.201 s

Mean RMSE: 2.883 s
Std RMSE:  0.202 s

Mean R²:   0.9224
Std R²:    0.0174
```

---

## Hyperparameter Tuning

V10 performs a controlled comparison of five Gradient Boosting configurations.

The goal is not to perform an exhaustive search, but to demonstrate a reproducible model tuning workflow.

| Configuration | Estimators | Learning rate | Max depth |
|---|---:|---:|---:|
| Baseline | 100 | 0.10 | 3 |
| More Trees | 200 | 0.10 | 3 |
| Lower Learning Rate | 100 | 0.05 | 3 |
| Deeper Trees | 100 | 0.10 | 4 |
| Balanced | 200 | 0.05 | 3 |

The results were:

| Configuration | Mean MAE | Mean RMSE | Mean R² |
|---|---:|---:|---:|
| Baseline | 1.813 s | 2.883 s | 0.9224 |
| More Trees | 1.977 s | 3.162 s | 0.9071 |
| Lower Learning Rate | 1.735 s | 2.635 s | 0.9353 |
| Deeper Trees | 2.023 s | 3.276 s | 0.9004 |
| Balanced | 1.790 s | 2.856 s | 0.9239 |

Among the tested configurations, reducing the learning rate produced the strongest cross-validation metrics.

Increasing the number of estimators or tree depth did not improve the results in this experiment.

---

## Final Model Configuration

The final V10 configuration selected from the tested configurations is:

```text
Gradient Boosting

n_estimators = 100
learning_rate = 0.05
max_depth = 3
random_state = 42
```

Final 5-fold cross-validation results:

```text
Mean MAE:  1.735 s
Std MAE:   0.175 s

Mean RMSE: 2.635 s
Std RMSE:  0.170 s

Mean R²:   0.9353
Std R²:    0.0143
```

Compared with the original Gradient Boosting configuration:

```text
MAE:  1.813 s -> 1.735 s
RMSE: 2.883 s -> 2.635 s
R²:   0.9224  -> 0.9353
```

The tuned configuration therefore improved all three evaluated metrics on the cross-validation experiment.

This does not establish that these hyperparameters are globally optimal. They were selected because they produced the strongest results among the configurations evaluated in V10.

## Feature Importance

The original Gradient Boosting model identified the following features as the most influential:

```text
shortest_stint_laps   0.419665
longest_stint_laps    0.302202
stint_lap_range       0.118487
hard_stints           0.117884
soft_stints           0.030818
medium_stints         0.009736
```

The first four features account for approximately 95.8% of the total feature importance.

This indicates that, within the generated simulation dataset, the distribution and length of stints have a strong relationship with the simulated race time.

This interpretation is specific to the simulation model and its assumptions.

## Prediction Error Analysis

The initial Linear Regression model was also examined through individual prediction errors.

For the held-out test set:

```text
Mean signed error:      -0.261 s
Mean absolute error:     3.215 s
Maximum absolute error: 15.291 s
Minimum absolute error:  0.002 s
```

The largest errors were concentrated in strategies with relatively high simulated race times.

This analysis provides an additional perspective beyond aggregate metrics and can help identify areas where a model struggles.

## Limitations

The V10 machine learning results have several important limitations.

### Synthetic data

The dataset is generated by the project's own race simulation rather than real Formula 1 race telemetry.

The model therefore learns relationships produced by the simulation assumptions.

### Simplified race model

The simulator does not represent the full complexity of a real Formula 1 race.

Real races involve factors such as:

- weather
- safety cars
- traffic
- overtaking
- tire temperature
- tire degradation differences
- fuel effects
- track evolution
- driver performance
- team performance
- accidents and retirements

These factors are outside the current model scope.

### Limited dataset size

The experiment uses 441 generated strategies.

A substantially larger and more diverse dataset would be required for stronger statistical conclusions.

### Feature representation

The model uses manually engineered strategy features.

More advanced approaches could learn richer representations from detailed lap-by-lap simulation data or real race telemetry.

## V10 Conclusion

V10 establishes a complete machine learning evaluation workflow for the F1 race strategy simulator.

The project now supports:

- supervised regression
- multiple model architectures
- baseline comparison
- train-test evaluation
- k-fold cross-validation
- prediction error analysis
- feature importance analysis
- controlled hyperparameter tuning
- final model evaluation

The final tested configuration is Gradient Boosting with 100 estimators, a learning rate of 0.05, and maximum tree depth of 3.

The next development stage can therefore move beyond predicting strategy race time and use machine learning as part of the actual strategy-selection process.
